## 0. 结论先行

当前标签/分类“不能点击查看”的**已证实主因是产品交互入口缺失，不是已证实的遮挡或点击层被覆盖**：

1. 现有 `LabelsPanel` 把分类和标签作为任务页中的资源管理/筛选控件渲染，没有独立“标签页”“分类页”、资源详情页或“进入列表”的导航入口。
2. 现有资源项的点击只调用 `onFilter(kind, value)`，改变任务列表筛选状态；它不是资源浏览页，也不显示资源下的任务列表、计数或详情。
3. 现有代码确实从 qB 读取 `torrents/categories`、`torrents/tags`，任务筛选使用 `torrents/info` 的 `category/tags` 字段；因此不能把问题归因于“完全没有读回”。但当前展示没有将每个资源的任务计数作为独立数据契约读回或计算后呈现。
4. 截至本审计没有代码证据证明标签/分类被遮罩、透明层或错误 z-index 阻挡。静态截图也不能证明真实点击行为；该项仍需运行时交互验证。
5. 1.3.6 包审计明确为 `TEST_CANDIDATE_NOT_ACCEPTED`，缺少“PT/labels/409 packaged regression”和 NAS/物理手机验收；不能把它当作最终已验收界面。

因此本轮设计不声称“修复已完成”，而是定义可实现、可回读、可验收的浏览和筛选主线。

## 2. 产品目标与非目标

### 2.1 本轮目标

- 标签页和分类页分别作为可到达的资源浏览入口。
- 资源项显示**来自真实 qB 任务快照的计数**，并区分读取中、读失败、无数据和筛选后为零。
- 点击标签/分类进入该资源的任务列表；任务名进入现有任务详情。
- 支持搜索、单选/多选筛选、清除筛选和从列表返回。
- 分类显示 qB `savePath`，但默认不提供移动文件动作，不因浏览或筛选改变路径。
- MoviePilot 和 qB 的数据来源、状态契约、失败/权限/无后端语义保持可审计。
- 手机优先：顶部筛选、底部导航、底部抽屉/全屏页、44px 触控目标、无横向溢出。

### 2.2 非目标

- 本轮不修改 `src/`、`gateway/`、`native/`、manifest、FPK、qB 配置或真实任务。
- 不改变 qB Web API 语义，不把前端 local state 或假计数当作后端事实。
- 不自动创建、重命名、删除分类，不自动移动文件，不修改 `savePath`、auto-TMM 或 `app/preferences`。
- 不把 MoviePilot 连接器的“可连接”状态冒充标签/分类读回成功；MoviePilot 仍通过既有标准 qB 兼容契约，真实连接器验收另行进行。
- 不在本轮增加批量 mutation；本设计只定义筛选多选和未来实现门禁，资源赋值写入仍须独立确认和真实读回。

## 5. 交互契约

### 5.1 入口、浏览和返回

- 标签/分类导航是显式按钮，不依赖点击标题或点击无边界文本。
- 资源行/卡片主区域是一个可聚焦按钮，触控区域至少 44×44px；名称、计数、状态属于同一主入口。
- 资源详情不是编辑页：只显示名称、真实计数、任务列表和后端更新时间。分类显示 `savePath`，复制路径是非破坏性动作。
- 任务名或独立“详情”按钮进入现有任务详情；返回保留资源和筛选条件、滚动位置和搜索词。
- 遮罩仅在 `event.target === event.currentTarget` 时关闭；返回键/ESC 关闭抽屉或全屏页的当前层，不跳回任务首页。
- 点击反馈只在按压且控件非 disabled 时短暂表现；请求结束必须清理 `busy/pressed/aria-busy`，不保留残影。

### 5.2 搜索、单选/多选、清除

- 资源页搜索按资源名称本地过滤，但资源集合必须先来自真实 qB 读取；搜索无结果显示“没有匹配的标签/分类”，不是“没有任务”。
- 资源任务页默认单资源筛选；任务页高级筛选支持分类单选或多选、标签单选或多选。多选同一维度为 OR，分类与标签两个维度之间为 AND；状态与文本搜索继续 AND。
- `全部` 清除该维度；“清除全部”清除所有资源、状态和搜索条件，并重新显示完整任务列表。
- 多选应用只改变读取筛选，不触发 `setCategory`、`addTags`、`removeTags` 或文件操作。筛选按钮文案不得使用“应用到任务”。
- 计数必须与当前同一份任务快照对应；快照刷新期间显示“更新中”，不能瞬间显示前端猜测值。

### 5.3 分类路径与移动风险

- 分类卡片显示 qB `savePath` 原值；空值显示“未设置/由 qB 默认策略决定”，不擅自替换成浏览器默认路径。
- 不提供拖拽文件到分类、不提供“移动文件”“整理文件”“应用路径”快捷操作。
- 若未来编辑分类路径，必须独立确认影响 auto-TMM/现有任务，并按真实 qB 读回和文件不移动验收；本轮只设计浏览，不开放该写动作。

## 6. 数据来源与状态契约

### 6.1 qB 真实数据

| UI 数据 | 唯一来源 | 最低字段/规则 |
|---|---|---|
| 分类资源 | `GET /api/v2/torrents/categories`，经正式应用 API 客户端 | 分类名、`savePath`；不能从 localStorage 恢复 |
| 标签资源 | `GET /api/v2/torrents/tags` | 标签名；qB 逗号分隔限制继续沿用，不能伪造转义 |
| 任务列表与计数 | `GET /api/v2/torrents/info`，按同一刷新快照计算 | hash、name、state、progress、category、tags；计数由完整真实任务快照按明确规则计算 |
| 任务详情 | 现有任务详情正式 API/读回 | 进入详情后显示真实任务字段和局部失败状态 |
| 分类路径 | 分类响应 `savePath` | 只读展示；不把 MoviePilot 容器路径映射当作 qB savePath |

计数可以由完整 `torrents/info` 快照**确定性计算**，但必须标注“任务快照计数”，不能在只有资源名列表时凭空显示 0。无法读取任务列表时不显示 0，显示“计数不可用”。若未来 qB 提供专用计数端点，也必须定义与任务列表的一致性和刷新时序。

### 6.2 MoviePilot 契约

- MoviePilot 仍只通过已设计的标准 qB HTTP 兼容入口访问 qB；UI 不直接请求 `127.0.0.1:18080`、BT `49160` 或浏览器网关地址。
- MoviePilot 的连接状态只表示认证/版本/只读 API 探针的状态，不代表标签/分类页面已读回；资源页仍以当前 qB 真实 GET 为事实来源。
- MoviePilot 写入标签/分类（未来实现）必须遵循 `accepted → reading_back → confirmed/unconfirmed`；连接超时不自动重放，不以 HTTP 200/202 或前端状态显示成功。
- 路径映射（MoviePilot 容器路径 ↔ qB NAS 路径）与分类 `savePath` 是两个契约；本轮不合并展示、不自动修改。

### 6.3 状态机

```text
UNINITIALIZED
  └─ loading_resources ─┬─ READY
                         ├─ NO_BACKEND
                         ├─ PERMISSION_DENIED
                         └─ LOAD_FAILED
READY
  ├─ resource search/filter → FILTERED / FILTERED_EMPTY
  ├─ resource click → RESOURCE_TASKS_LOADING → RESOURCE_TASKS_READY
  ├─ refresh → REFRESHING → READY / LOAD_FAILED_KEEP_OLD
  └─ task click → TASK_DETAIL_LOADING → TASK_DETAIL_READY / PARTIAL_FAILED
```

| 状态 | 显示 | 允许动作 | 禁止误导 |
|---|---|---|---|
| loading | 骨架或“正在读取标签/分类/任务” | 返回、取消当前层 | 不显示空列表/0 计数 |
| ready | 资源、真实计数、更新时间 | 搜索、筛选、进入任务列表 | 不显示未经快照支持的计数 |
| no backend | qB 后端不可达/未配置 | 重试、返回设置 | 不清空旧数据为“无数据” |
| permission denied | 无权访问，显示安全 reason code | 重试、回正式入口 | 不提示暴露 18080 |
| load failed | 端点与可执行建议，保留旧数据 | 重试、返回 | 不把失败当空态 |
| empty resources | 真实读取成功但无标签/分类 | 返回任务、创建入口（若未来授权） | 不与失败态混用 |
| filtered empty | 当前搜索/筛选无结果 + 清除 | 清除、调整条件 | 不说“没有任务” |
| unconfirmed | 请求送达但读回未确认 | 人工刷新 | 不自动再次 POST |

## 7. 视觉与交互原则

1. 手机优先但不把桌面表格压缩到手机；任务卡片纵向排列，名称可换行，长分类/标签使用完整文本或可展开，不强制省略为不可识别短码。
2. 所有可点击控件最小 44×44px，焦点可见，颜色不是唯一状态信号。
3. 页面 `overflow-x: hidden` 不是修复方案；布局必须通过可换行、纵向堆叠和内容滚动消除横向溢出。
4. 资源页和任务页区分“浏览入口”“筛选控件”“危险操作”；不在一个小 chip 内嵌套删除/编辑点击区。
5. 计数、路径、更新时间和错误 reason code 使用与数据来源一致的文案；不把“已保存配置”写成“后端已连接”。
6. 加载、失败、权限、无数据和筛选无结果均有独立视觉状态；旧数据保留时明确标注旧快照/刷新失败。
7. 按钮无延迟点击高亮残影；异步请求期间 disabled、`aria-busy=true`，成功、失败、取消、返回都清除状态。

## 12. 选择模式状态模型

```text
BROWSE
  └─ 点击“选择” → SELECTING(selectedHashes=[])
SELECTING
  ├─ 勾选任务 → SELECTING(selectedHashes += hash)
  ├─ 全选 / 反选 / 清除 → SELECTING(updated selection)
  ├─ 批量动作 → EXECUTING(action, pendingHashes, completed, failed)
  │    └─ 每个 hash: POST → GET torrents/info(hash) → CONFIRMED | FAILED
  └─ 退出/返回/错误结束 → BROWSE(selectedHashes=[])
```

- 默认 `BROWSE` 不渲染任务 checkbox，也不保留选择状态；只显示一个“选择”入口。
- `SELECTING` 才显示 checkbox：视觉方框约 24×24px，外层触控容器固定至少 44×44px；键盘 focus 必须可见。
- `selectedHashes` 只包含当前任务快照中仍存在的 hash。刷新/过滤后清理不可见或不存在的选择，退出选择模式无条件清空。
- 任务 `selected` 是独立于 `active` 的高亮：选中任务使用明确背景、边框和左侧标识，不只依赖颜色。
- 全选只选择当前可见任务；反选在当前可见集合内取补集；清除清空全部已选 hash。

## 13. 标签/分类状态与对比

标签/分类资源按钮使用互斥且可审查的状态：

| 状态 | 触发 | 视觉/语义要求 |
|---|---|---|
| `default` | 非交互 | 中性表面、常规边框 |
| `active` | 当前资源浏览页/当前筛选维度 | 蓝色强调、`aria-current` 或等价语义；不可与 selected 混淆 |
| `hover` | 指针悬停 | 轻微表面变化，不改变布局、不冒充选中 |
| `focus` | 键盘/辅助技术聚焦 | 3px 可见 focus ring，不依赖 hover |
| `selected` | 选择模式中该资源对应的任务/资源筛选已选 | 强调背景 + 边框/图标；持久存在直到清除，不用 pressed 残影代替 |

任务列表的 active 筛选与 checkbox selected 必须同时可见；标签/分类行被当前资源打开时有 `.active`，资源管理 tab 的 active 只表示当前浏览维度。hover/focus 不能触发 qB mutation。

## 14. 批量操作与响应式承载

- 进入选择模式后显示“全选、反选、清除、退出”；选择数量为 0 时批量动作 disabled/隐藏，不能发空 mutation。
- 批量动作包括：开始、强制开始、暂停、设置标签、设置分类。删除不进入默认批量菜单；单任务删除仍须确认。
- 桌面使用置顶 toolbar；手机使用底部 sheet，sheet 在安全区内固定底部，内容可滚动，内部点击不关闭，遮罩仅 `target === currentTarget` 关闭。
- 设置标签/分类必须显式选择/输入后确认；不能把筛选标签误当成写入目标。分类路径不因批量设置改变。
- 每个任务逐项执行，并在每项请求后读取 `torrents/info?hashes=<hash>` 确认 action/state/force_start 或 category/tags；不以一次 `hashes=a|b` 的 200 代替逐项读回。
- 批量执行期间显示进度、已确认数和失败数；失败项保留 hash/任务名和安全 reason。部分失败明确显示“已确认 N，失败 M”，不自动重放、不静默跳过。
- 成功/失败/取消/退出都清理 `busy`、pressed 和 `aria-busy`；不可留下点击残影。
